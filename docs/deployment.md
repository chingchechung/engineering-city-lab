# Static deployment and regression

Phase 4 candidate, prepared 2026-10-24 (Asia/Taipei). This procedure creates local
files only. University deployment and release publication are instructor steps
after review; no workflow uploads anything.

## Build the static candidate

From the reviewed checkout, with Python 3.12 or later:

```sh
python3 tools/package_release.py --output /tmp/engineering-city-lab-release
```

Windows equivalent: `py -3 tools/package_release.py --output C:\Temp\engineering-city-lab-release`.
The destination must be new and outside the checkout. Choose another destination
for subsequent builds; the script never deletes or merges an older package.
There is no npm install, bundler, archive or runtime content transformation.
Identical source produces identical file names and bytes (filesystem timestamps
are not a release identity).

The package has **47 files**: `index.html`, all **40 native modules** under `js/`
(including the generated geographic database), three stylesheets under `css/`,
`assignments/manifest.json`, `LICENSE` and `THIRD_PARTY_NOTICES.html`. The local
module/style graph is the explicit copy boundary. New asset types require review.
City geometry, textures and audio are generated by those modules; no separate
local images, sound files or font files are needed. Three.js/addons and fonts
remain external. Existing data transformation inputs in `tools/data/` are not
runtime files; the notices link the exact source revision and distributed
machine-readable geographic database.

The script validates the manifest and **requires an empty units list**. It copies
only that assignment file even if additional JSON exists beside it. It excludes
tests/fixtures, private drafts, teacher_data, export, tools, schemas, development
docs, Git, credentials, backups, caches and screenshots. It rejects missing inputs,
runtime symlinks and unsafe/root-relative runtime paths. It validates inputs before
creating the destination. Copy interruption can leave an incomplete directory;
use a fresh destination and rerun, then run the checks below. Do not upload a partial
package or the repository root. Publishing real assignments is a later explicit
[teacher operation](teacher-publishing.md), never part of packaging.

## Verify locally before upload

```sh
python3 -m http.server 8000 --bind 127.0.0.1 --directory /tmp/engineering-city-lab-release
```

Open `http://127.0.0.1:8000/`, refresh, open Assignments (empty), and check Demo.
For a realistic nested URL, place the generated folder under a temporary web
directory, for example `web/~username/engineering-city-lab/`, serve **web**, then
open `http://127.0.0.1:8000/~username/engineering-city-lab/`. Keep the trailing slash;
normal directory redirect or direct `index.html` also works. The automated release
tests create this physical layout and check every packaged file's exact HTTP
bytes, JS/CSS/JSON MIME types, redirects, repeat/direct navigation, UTF-8 fixture
JSON in an isolated test copy, and genuine missing-file 404s. No fixture goes in
the real candidate.

## Manual Apache installation

1. Obtain a working **HTTPS** university URL and static directory, potentially
   `/~username/engineering-city-lab/`. Browser WebGPU requires a secure context
   (HTTPS in production; loopback HTTP is suitable for local tests). An HTTP-only
   server is a release blocker until HTTPS is provided. Check the real browser's
   WebGPU availability and developer-console errors.
2. Upload the candidate directory's contents and retain the `css/`, `js/` and
   `assignments/` hierarchy, case-sensitive file names and both notices. Keep a
   previous approved package outside the public directory for rollback.
3. Use ordinary `DirectoryIndex index.html` / static file serving. No rewrites,
   SPA fallback, PHP, Node, database, server sessions or additional Apache module
   is required. Ask the administrator to serve `.js` as `text/javascript` or
   `application/javascript`, `.css` as `text/css`, `.json` as `application/json`
   and `.html` as `text/html`, with UTF-8 text. A default static installation
   usually provides this; no `.htaccess` is shipped or assumed supported.
4. Verify a missing JS/JSON file returns **HTTP 404**, never a 200 login page,
   custom HTML fallback or redirect. The assignment loader rejects redirects.
   Root directory redirect is fine; module and JSON URLs must be direct.
5. Avoid long-lived immutable caches for mutable `.js`, HTML or assignment JSON.
   The loader requests JSON with `cache: no-store`; server/CDN behavior must also
   permit fresh files. Disable directory listing where administratively available;
   this does not make known public file URLs private.
6. Open the final nested URL and direct `index.html`, refresh, check network MIME
   types and Chinese/English text, external dependencies and empty Assignments.
   Then complete the [Windows checklist](release-checklist.md). No university
   access or actual server configuration has been tested by this cloud task.

For upgrades, prefer uploading into a new version directory and switching the
public link after verification. Otherwise schedule maintenance for a complete
replacement: mixed HTML/module versions during multi-file uploads are unsafe.
Restore the previous approved package for rollback; keep teacher publication and
its private backups separate. A full page reload discards current practice progress.

## Dependencies and privacy

No backend runtime is required on Apache. The browser still needs a compatible
WebGPU device/browser, CDN access to the unchanged Three.js `@dev` import map
and optional Google Fonts access. Fonts have system fallbacks; CDN failure prevents
the city from loading. Floating dependencies can change after this candidate was
tested. See the [separate pinning recommendation](upstream.md#phase-4-release-audit).
No offline bundle or changed versions are included.

Public JSON, source and correct answers can be downloaded directly. No practice
answers or progress are sent to a project backend; progress exists only in memory
and is lost on full reload. Existing city position/sound preferences may use
localStorage; they are not assignment persistence. The project adds no student
identifiers, authentication, grades, analytics, tracking cookies or database.
Normal university/CDN/font server request logs and YouTube/Google Forms policies
remain external. Form submissions are handled only by Google Forms, with no
completion callback to this app. This is practice, not a confidential exam platform.

## Regression and CI

Development-only tools: Node 24, Python 3.12, `jsonschema==4.26.0`. Browser scripts
add Python Playwright and Chromium (or installed Chrome/Edge for headed review).
None is needed on the static server.

```sh
python3 -m pip install jsonschema==4.26.0
node --test --test-reporter=tap tests/*.test.cjs tests/*.test.mjs
python3 -m unittest tests.test_assignment_contract tests.test_release -v
python3 tools/check_release.py --syntax
python3 tools/check_release.py
python3 tests/browser_learning_dom.py --output /tmp/city-phase4-dom
python3 tests/browser_release.py --site-root /tmp/engineering-city-lab-release --output /tmp/city-phase4-static-browser
python3 tests/browser_education.py --workflow --base-path course/city/ --site-root /tmp/engineering-city-lab-release --output /tmp/city-phase4-browser
```

The optional `--site-root` serves and instruments main from the **generated
package**, with test fixtures provided only by test routes. Existing behavior
without the flag still serves the repository. Full-city software WebGPU checks
use the documented test scheduler/cached CDN bytes and do not benchmark hardware.
All dummy video/Form requests are intercepted before navigation. The separate
static browser checks real tilde-prefixed navigation/modules/attribution without
initializing a second renderer, and blocks external requests.

`.github/workflows/regression.yml` runs the Node suite, Python contract and release
tests, syntax, schemas and empty-manifest/runtime integrity on PRs and explicit
manual dispatch. It uses Ubuntu 24.04, Node 24, Python 3.12 and versioned official
setup actions. Only `contents: read` permission is requested; there are no secrets,
deployment jobs, releases or publishing permissions. Visual WebGPU checks remain
the full-strength documented cloud/manual commands, outside this lightweight CI.
